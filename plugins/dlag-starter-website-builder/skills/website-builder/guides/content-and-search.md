# Repository content and search metadata

Use reviewed JSON or TypeScript data objects for pages and posts. An initial content model needs a stable slug, title, summary, publish state, canonical route, body blocks and optional reviewed image/alt text. Render body blocks as ordinary React text and approved components. Do not use eval, executable user MDX or unchecked HTML. Repository imports are trusted source code and need review; remote/user content remains data. If Markdown is explicitly selected later, parse it without raw HTML and sanitize after the last unsafe transform. Do not assume an HTML sanitizer makes MDX expressions safe.

Keep draft posts out of public loaders, navigation, sitemap and feeds. Resolve slugs through a finite reviewed content map rather than concatenating an untrusted filesystem path. Validate content structure at build/load boundaries. An AI edit changes the content source, then route output is checked against that saved value. A source edit is not automatically a hosted publication.

Keep one metadata approach consistent with the installed project. React 19 can render title/meta/link elements in route components; an existing React Router meta export needs Meta in the root head and links exports need Links. Child meta arrays replace parent arrays, so return a complete page set or compose intentionally. Avoid duplicated competing titles and canonicals. See the [route recipe](../templates/site-route.md).

Every public page needs a specific title/description, a canonical from the approved site origin plus normalized route, sharing metadata where used, an H1 and useful internal links. Do not derive the canonical origin from an arbitrary request Host header. Preview domains should not silently become canonicals. Preview noindex and crawl policy are explicit environment decisions. Noindex is not an access-control mechanism.

Serve robots.txt as text/plain and sitemap.xml as application/xml using framework resource-route loaders with Response, preserving actual HTTP statuses. Enumerate only public canonical routes and published articles. Escape XML, remove duplicate URLs and never include private or draft paths. Last-modified dates come from real content changes, not the current clock on each request. A robots exclusion does not secure private content.

Use JSON-LD only for facts present on the page, such as Organization, WebSite, BreadcrumbList or a real BlogPosting. Never invent ratings, reviews or author credentials. Serialize JSON-LD with JSON.stringify and escape '<' as '\u003c' before embedding in a script element, preventing user text from closing that element. Document the narrow trusted serializer; do not broadly allow raw content HTML. Structured data validity does not promise a search feature, ranking or AI citation.
