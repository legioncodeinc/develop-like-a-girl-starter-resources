# Application Integrations procedure

1. Identify the requested provider, direction, owner mapping, payload fields and side effects before writing its adapter. Use the [integration contract](../templates/integration-contract.md). No CRM, automation service or background runner is selected by this Playbook. If none was requested, stop at the contract and ask which provider the feature needs.
2. Read the provider's current primary API documentation and installed SDK. Put credentials in approved Cloudflare secrets through `dlag-starter-core:secrets`, keep adapters server-only and use `dlag-starter-core:implementation-foundation` for validation and HTTP semantics. Mock the adapter until real use is authorized.
3. Build outbound URLs from a fixed HTTPS origin and fixed routes. Never accept arbitrary URLs, hostnames, ports or redirect destinations from user data. Use the [request recipe](../examples/fixed-provider.server.ts), reject redirects, set a timeout, bound response bytes and validate parsed JSON as unknown before consuming it. Return a safe error and request ID without keys or private payloads.
4. Retry only transient responses the provider documents, with a small attempt limit, bounded delay and Retry-After handling. A write needs the provider's supported idempotency key, bound to the owner, operation and stable payload digest. Retrying an unsupported write risks duplicate charges or records. Preserve failed status for a user retry without changing the stable key for the same operation.
5. For webhooks, read the raw body within a limit, verify the provider signature/timestamp with its official SDK before parsing or applying changes, validate event type/schema and map provider account/object IDs to the correct app owner. Store an event ID plus payload digest under a unique constraint; reject a reused ID with different content. Claim processing and apply the database mutation in one transaction; retries may resume documented failures. A successful HTTP acknowledgment requires durable acceptance, not an in-memory promise. Do not launch an unselected queue.
6. Exercise signature failure, stale timestamp, unknown owner, duplicate ID, changed payload, timeout, rate limit and partial failure using local mocks. Save the contract and exact evidence. Live connectivity, credentials, third-party state and delivery remain pending. Use `dlag-starter-core:ready-check` without claiming mock results as provider proof.
