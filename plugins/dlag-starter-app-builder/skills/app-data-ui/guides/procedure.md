# Application Data UI procedure

1. Inspect the record shape, owner rules, expected row count and requested actions. Use the [data screen contract](../templates/data-screen.md). Default to a native table and React Router loaders/forms for a small screen. A basic sortable table does not require a new package. If the project already needs TanStack, use its React adapter and check the installed API; do not transplant Svelte runes, Svelte adapters, TanStack Router or TanStack Start into this stack.
2. Filter by verified owner on the server before sorting, pagination, counts or exports. Accept only fixed known sort columns/directions, bounded page size and a validated cursor/page number. Keep URL search parameters as the shareable list state. Reset the page when a filter changes, add a stable tie-breaker and label previous/next actions.
3. Render a caption, header cells with scope, buttons with meaningful names and the current `aria-sort`. Provide labelled filters, loading/error/empty results and keyboard access. Never make a whole clickable row the only way to open a record. Use `dlag-starter-core:ui-primitives` for dialogs or complex controls.
4. For CSV export, select approved columns from the current user's permitted scope. Cap export size or paginate deliberately; do not silently export an unbounded database. Use the [CSV helper](../examples/csv.mjs) for quoting and formula-prefix mitigation. Keep raw stored values intact and neutralize only spreadsheet output. Correct MIME type and a fixed safe attachment filename belong on the response. CSV mitigation is defense in depth; spreadsheet programs and save/reopen behavior still require the actual target application to be checked.
5. For import, use an existing CSV parser with quoted-field support. Reject unsupported encoding, oversized files/row counts, duplicate headers and missing required columns. Show a mapping preview and collect row number, field and readable error for every invalid row. Validate on the server again, derive owner from the session, reject unexpected keys and use a transaction or explicitly approved partial-import policy. Never overwrite records by untrusted owner/id fields.
6. XLSX is optional guidance until specifically requested. Reuse an installed maintained parser only after checking its runtime/buffering limits and formula cells; do not install a package or promise streaming support implicitly. Large files need bounded processing; a Worker does not create unlimited memory. Save the [data screen contract](../templates/data-screen.md) and report actual import/export cases with `dlag-starter-core:ready-check`.
