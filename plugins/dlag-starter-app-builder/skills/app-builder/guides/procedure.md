# App Builder procedure

1. Read the user's request, existing code, package versions and Project Notebook. Reuse approved decisions. Ask only unresolved questions that change the first usable slice. Use `dlag-starter-core:project-planning` to save a bounded brief with the [app brief](../templates/app-brief.md).
2. Draw the routes and data boundary before editing: login, workspace list, create, detail/edit, private download and logout. Use `dlag-starter-core:identity`, `dlag-starter-core:data-foundation` and `dlag-starter-core:implementation-foundation`. The server verifies the session for every protected loader/action, binds ownership to that verified user, and relies on tested RLS in Supabase. Hidden buttons are not permission checks.
3. Build the shell and one complete record journey first using `dlag-starter-core:react-router-ssr`, `dlag-starter-core:design-foundation` and `dlag-starter-core:ui-primitives`. Give forms labels, inline errors, pending states, focus recovery, empty states and a clear next action. Keep credentials and provider clients in server modules. Use request-scoped clients; never serialize tokens into loader data.
4. Apply `dlag-starter-app-builder:app-data-ui` for sorting, filtering, pagination and safe exports. Add `dlag-starter-app-builder:app-onboarding` after the first usable action works. Add `dlag-starter-app-builder:app-search` or `dlag-starter-app-builder:app-integrations` only for requested features. These are Playbook handoffs, not claims another agent ran.
5. Use `dlag-starter-core:r2-storage` for private uploads/downloads: use an authenticated Worker route that checks ownership before streaming the file; enforce size/type limits and store an opaque object key with its metadata. Use short-lived S3-compatible presigned links only when the project explicitly selects direct transfer. Never trust a submitted object path. Use `dlag-starter-core:resend-transactional` for requested mail. Save the main change first, record delivery separately and avoid resubmitting the main change when mail fails. No newsletter sends or unselected queue provider.
6. Payments are optional. Use `dlag-starter-app-builder:stripe-payments` only when requested and available, with Starter's hosted checkout. Report a missing optional Playbook rather than inventing an integration. Use local mocks until provider access is authorized.
7. Read changed files back. Exercise the affected signed-out, owner, other-user, validation, duplicate-submit, empty, error and keyboard cases with `dlag-starter-core:browser-checks` when tools exist. Reuse passing evidence when its inputs are unchanged. Save the [build report](../templates/build-report.md) and hand off to `dlag-starter-core:ready-check`. Unrun compilation, browser, RLS, mail and provider checks stay pending.
