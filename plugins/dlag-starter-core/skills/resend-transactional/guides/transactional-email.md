# Prepare one transactional message per event

Resend is transactional only in this kit. Do not create Broadcasts, Audiences, newsletters, marketing campaigns or mailing-list flows. Supabase Auth uses Resend through custom SMTP for its authentication mail. App notifications originate in the Worker using Resend's API. Those are distinct paths with separate sender/settings decisions; the application must not duplicate Supabase recovery messages.

Inspect the actual business event before drafting an email. Derive recipient and event ownership from verified server data, select a reviewed transactional template and minimal payload, and store one durable delivery intent tied to that event. Client-supplied recipient, sender, subject or arbitrary HTML must not become an open email relay. Escape untrusted template text. Avoid embedding private file links in an email by default; the destination can be an authenticated app route that rechecks authority.

The [HTTP request example](../examples/send-transaction.server.ts) illustrates a server-only Resend call using a persisted event key and validated prepared message. It is not automatically invoked. The owner must authorize a real send. Resend accepting a request is not confirmation of delivery or permission to grant access.

Use a durable uniqueness constraint for the business event plus message purpose. Atomically write the intent with the business change when both reside in the same database transaction, so a failed request does not lose the email and a retry does not invent another event. A privileged outbox should not accept arbitrary user writes; isolate it from exposed client access and define narrowly scoped processing authority. Use a stable Resend idempotency key for the same immutable payload across retries. Do not generate a random new key every attempt.

Persist prepared, sending, accepted, delivered, failed and unknown outcomes as appropriate, with provider ID and sanitized errors. A timeout after sending means unknown, not definitely unsent. Reconcile uncertain attempts and use the same key/payload within the provider's documented retention window. After that window, do not automatically resend an uncertain event. App-side uniqueness and reconciliation remain necessary. Do not promise exactly-once delivery from an HTTP request.

Choose an execution trigger that fits the requested feature. For a small transactional flow, the Worker can attempt delivery synchronously after the business change and intent are durably saved. Claim the intent atomically before sending, use a bounded request and response read, persist the result, and return the saved business result even when email fails. Concurrent requests must not both send the same intent. The packaged HTTP helper needs those application-owned timeout, response-size, claim and persistence boundaries before use with a real transport. An API acceptance is still not delivery.

An authorized retry action can resume a failed intent with the same payload and key; an uncertain attempt requires reconciliation before resending, especially after the provider retention window. This simple path does not need a new background provider. Use a separate runner only when the requested delivery guarantees need one. No background provider, schedule or queue is selected by this Playbook. Record the chosen trigger, failure recovery and authority in the [worksheet](../templates/email-plan.md).

Check duplicate event, concurrent attempt, missing sender/key, unauthorized recipient and ambiguous response cases. Keep delivery webhooks signature-verified before changing state when a later task implements them; a callback alone never creates user permissions. Sender-domain DNS and Supabase SMTP setup remain provider operations requiring explicit approval.

The packaged examples are adaptation inputs. Check local syntax and project integration only when tools permit. No Supabase SDK, React Router lifecycle, RLS execution, R2 persistence or email delivery is established by the pure helper fixture. A successful stub result must stay labeled fictional.
