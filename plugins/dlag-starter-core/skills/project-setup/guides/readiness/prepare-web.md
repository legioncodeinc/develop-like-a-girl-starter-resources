# Prepare a web product's launch assets

Prepare only the accounts, assets and accountable owners needed for the intended web milestone. Return a detailed readiness table and immediate blockers. A preparation request does not authorize account access or provider changes.

1. Confirm public website versus authenticated app, intended users, stored records, file access, transactional email and optional payment flow. Preserve the approved Starter architecture: GitHub, React/Vite with React Router framework SSR, Workers, Supabase database/auth, Cloudflare secrets, R2 and transactional-only Resend. Ask only unresolved product questions that change this milestone; do not select another full stack.
2. Inventory domain/brand/content ownership, repository access, Workers project/environment reference, HTTPS responsibility, support contact and content/media rights. Website content is edited in the repository; no separate CMS editor account is required. Ask whether hosting manages TLS before proposing manual issuance. A domain name alone does not prove ownership or working DNS.
3. Add Supabase database and auth assets only when the accepted product uses them. Separate project existence from production permission policies, capacity, backup/recovery evidence and auth-email readiness. Supabase Auth identifies the customer; record ownership and file-access rules still need server checks. R2 holds bytes while Supabase records application ownership. No Supabase Edge Function backend is assumed.
4. For social sign-in, record only the explicitly selected identity provider's project, callback, brand/contact and requested scopes by environment. A Supabase test login does not prove a social provider's production approval. Conditional provider verification is a separate readiness item; do not require every social provider.
5. Add Resend only for transactional mail, with sender/domain ownership, environment and delivery/recovery responsibility. Do not add newsletter audiences or broadcasts. Add Stripe only when money moves through optional hosted Checkout: business/environment reference, webhook-signature custodian, entitlement/recovery owner and billing design. A successful return URL is not payment entitlement.
6. For the intended paid-user milestone, assign error/availability/alert/support/recovery responsibility before selecting any extra vendor. Record budgets, rate units and uncertainties without invented operating costs. A queue or job provider remains undecided; an outbox proposal is not an installed runner.
7. Fill the [detailed ledger](../../references/readiness/ledger-contract.md), link prerequisites, flag immediate blockers and defer unused assets with reasons and triggers. Return editable rows, one preparation summary and named next-owner actions. No DNS/provider/account/credential action occurs here.

Use current supplied official requirement captures and their dates. If none is available within this role's local read scope, record the precise research gap; do not pretend requirements or account state were checked. See [qualification](qualify-assets.md).
