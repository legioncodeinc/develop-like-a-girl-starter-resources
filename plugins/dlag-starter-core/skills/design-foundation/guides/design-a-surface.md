# A focused surface pass

Find the task, audience, approved direction and requested edit boundary. If the request says polish, preserve the existing structure and identity. If it asks for redesign, identify the actual accepted change in direction before replacing an existing system. Keep unanswered preferences distinct from implemented facts.

Write a compact brief using the template, at the project's existing documentation location when saving documentation is requested. For a new foundation record palette roles, display/body fonts, readable line length, spacing/radius scales, motion buckets and supported themes. Include a reason for each unusual rule. Use existing assets and licensed fonts; placeholder paths and example values are not a new brand.

Use CSS custom properties for foreground/background/action/error/focus roles. Map utility-facing variables with top-level Tailwind v4 `@theme` or `@theme inline` when referencing other variables. Do not insert a v3 JavaScript config into an existing v4 project. Keep class names complete strings so the scanner sees them. Reuse the project's installed Vite/Tailwind integration; do not install or upgrade it as a side effect.

Apply tokens to one complete task path before propagating a new pattern. Keep one main heading and primary action, text labels for controls, visible focus and useful empty/loading/error/success states. Use a responsive grid that can collapse with real content. Prefer rem-based type with optional bounded `clamp()` display sizes; retain readable text at zoom and do not lock body text to viewport units. Use named durations and reduced-motion rules. Do not add motion that hides status or is required to understand the task.

Record each relevant component's variants, keyboard behavior, disabled/pending/error states and actual source path. For a broader new system use brief, tokens, utilities, component notes, screen notes, illustrative examples and reader guide; do not demand hundreds of lines or a fixed component count for a small job.

In the single inspection batch check a narrow viewport and desktop, long text, keyboard traversal, clear focus, zoom/reflow, reduced motion and requested themes. Fix findings as one batch. If no app is running, report these as planned checks. Never install a detector or capture tool to manufacture a completion result. Return precise unfinished work when tools are absent.
