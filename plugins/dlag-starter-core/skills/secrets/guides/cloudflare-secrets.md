# Wire the requested binding

1. Identify the exact app directory, source Wrangler configuration, lockfile, existing SSR entry and requested local files. Read placeholder configuration only. Record which environment the request concerns and whether the output is a local draft or an authorized operational handoff.
2. Classify each name in the [binding map](../templates/binding-map.md): browser-public configuration, server-only configuration, secret text, or resource binding. A name ending in `KEY` is not sufficient evidence that its value is public.
3. Trace the server consumer. Workers supplies `env` at the request boundary. Use the project's existing React Router load context to reach server-only modules. Do not invent a new context property or bypass the project's adapter. Keep R2 as a bucket binding, rather than replacing it with an account key.
4. Validate only the names needed by the current operation. Missing or invalid configuration refuses that operation with a fixed message or binding name. Do not stringify `env`, request headers, cookies or provider responses to diagnose it. An optional email feature should not break an unrelated public page merely because its key is absent.
5. Keep the public return value an explicit allowlist. Supabase's URL and publishable key may be deliberately public. A Supabase secret key or legacy service-role key remains privileged server material. The example accepts only modern `sb_publishable_` keys and clean HTTPS `*.supabase.co` project origins. It rejects legacy JWT keys, private keys, credentials embedded in URLs, query strings and custom hosts. Verify the exact project against approved configuration separately; hostname and key format do not prove ownership. Never spread `env` into loader data or substitute private values through Vite's `define` or a `VITE_` name.
6. Use the [environment](01-environment-model.md) and [local-development](02-local-development.md) guides to diagnose configuration selection. An operator-owned ignored local file is a different destination from a hosted Worker secret. Neither automatically updates the other.
7. If hosted provisioning or rotation is requested as a draft, write the exact target, command effect and rollback limits from [provisioning](03-provisioning-and-versions.md) and [rotation](06-rotation-and-audit.md). Actual execution remains with the authorized operator.
8. Read the changed files back. Inspect imports, public return shapes and failure paths. Exercise synthetic boundary cases only when tools and task scope allow. A passing pure helper does not establish the application's bundle safety, provider delivery, authorization policies or deployed secret presence.

Use [bindings.server.ts](../examples/bindings.server.ts) as a self-contained boundary example. Replace its illustrative type with the project's existing generated types where available; do not install a generator for this task. The example has no provider calls and makes no assumptions about the SSR adapter's context shape.

Save the result in the project's requested destination with names, configuration paths and check results. Do not include raw credentials in a report, screenshot, patch, fixture, workflow output or chat.
