Starter uses React Router framework SSR, Cloudflare Workers and Supabase; optional library comparisons do not select a service.


## The default stack

**native React Router Form/fetcher for ordinary route forms; **React Hook Form + Zod** via an installed compatible resolver for complex client fields. React19 browser form Actions are a separate option, not required on top of router actions.

## The canonical React 18 / client form

```tsx
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';

const Schema = z.object({
  email: z.string().email(),
  password: z.string().min(12),
});
type FormValues = z.infer<typeof Schema>;

export function LoginForm({ onSubmit }: { onSubmit: (v: FormValues) => Promise<void> }) {
  const { register, handleSubmit, formState: { errors, isSubmitting } } =
    useForm<FormValues>({ resolver: zodResolver(Schema), mode: 'onBlur' });

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <label>
        Email
        <input type="email" autoComplete="email" aria-invalid={Boolean(errors.email)} {...register('email')} />
        {errors.email && <p role="alert">{errors.email.message}</p>}
      </label>
      <label>
        Password
        <input type="password" autoComplete="current-password" aria-invalid={Boolean(errors.password)} {...register('password')} />
        {errors.password && <p role="alert">{errors.password.message}</p>}
      </label>
      <button disabled={isSubmitting}>Sign in</button>
    </form>
  );
}
```

## The framework route action form

This focused route shows validation and pending/error wiring. The two *.server.ts imports are required project implementations: requireActor must verify the selected Supabase session and request origin; updateDisplayName must enforce the actor's ownership in persistence. They are not supplied by this example and must be Security reviewed before use. No browser parameter supplies actor identity.

```tsx
// app/routes/profile.tsx, route types generated by the existing framework.
import { Form, data, useNavigation } from 'react-router';
import type { Route } from './+types/profile';
import { requireActor, updateDisplayName } from '../services/profile.server';

export async function action({ request, context }: Route.ActionArgs) {
  if (request.method !== 'POST') throw new Response('Method not allowed', { status: 405, headers: { Allow: 'POST' } });
  const actor = await requireActor(request, context);
  const form = await request.formData();
  const raw = form.get('displayName');
  if (typeof raw !== 'string' || raw.trim().length < 1 || raw.trim().length > 80) {
    return data({ ok: false, value: typeof raw === 'string' ? raw.slice(0, 80) : '', error: 'Use 1 to 80 characters.' }, { status: 400 });
  }
  const displayName = raw.trim();
  await updateDisplayName({ actor, displayName, signal: request.signal });
  return { ok: true, value: displayName, error: null };
}
export default function Profile({ actionData }: Route.ComponentProps) {
  const navigation = useNavigation();
  const pending = navigation.state !== 'idle';
  return <Form method="post" aria-busy={pending}>
    <label htmlFor="display-name">Display name</label>
    <input id="display-name" name="displayName" defaultValue={actionData?.value ?? ''}
      required maxLength={80} aria-invalid={Boolean(actionData?.error)}
      aria-describedby={actionData?.error ? 'name-error' : undefined} />
    {actionData?.error && <p id="name-error" role="alert">{actionData.error}</p>}
    <button disabled={pending}>{pending ? 'Saving...' : 'Save'}</button>
    <p role="status">{actionData?.ok ? 'Saved.' : pending ? 'Saving...' : ''}</p>
  </Form>;
}
```

Use the application's bounded body parser and trusted session/CSRF policy before this action in production. request.formData alone does not impose a byte limit. Preserve entered values on invalid results and errors, and do not echo passwords/tokens back in action data. The router supplies pending state and revalidation; no RSC or React useActionState is needed for this flow.

## Share schemas

The Zod schema is defined **once** and imported by both the client (React Hook Form resolver) and the server (route action validation). This is the canonical "validate at the boundary twice: client for UX, server for security" pattern.

## Accessibility requirements (non-negotiable)

- Every input has an associated `<label>` (not placeholder-as-label).
- Errors are announced via `role="alert"` or `aria-live="polite"`.
- Submit button is disabled during submission, not hidden.
- Error summary at top for long forms, linking to each field.
