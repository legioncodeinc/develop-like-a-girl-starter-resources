# Build React/Vite against a separate backend

Use installed project versions. Code fences are focused examples with project imports identified, not complete applications or executed receipts. Additional packages, tools, provider setup and configuration require the applicable user authorization. Starter uses React Router framework SSR, Cloudflare Workers and Supabase; optional library comparisons do not select a service.

Use when the browser UI and API have separate runtimes. First record installed React/ReactDOM/Vite versions, existing scripts, router/data library, API schema and hosting origins. Starter keeps Workers as hosting/custom-backend owner and framework SSR as the rendering strategy. Record API boundaries within that selected topology; do not switch to a SPA or Go service from this method. A Vite client build alone supplies neither an API server nor React Server Components. Framework SSR also needs the actual server entry/runtime.

1. Write the boundary record from the [worksheet](../templates/outcome-boundary-record.md): browser UI, API server, database, identity issuer, development proxy and production URLs. Keep server credentials and privileged mutations on the API. VITE-prefixed configuration is exposed in client bundles. A development proxy is not production routing or an authorization control.
2. Preserve method/path, request validation, response schema, status/error semantics, session transport, expiry/refresh, tenant identity and pagination. UI visibility is not authorization. Surface server authorization/CSRF/CORS concerns to Security, preserve existing controls until reviewed.
3. Choose the existing router loader/query layer. Keep request parsing and fetch errors at the API boundary; handle loading, empty, forbidden, unavailable and retry states. Maintain credentials behavior deliberately; cross-origin cookie requests require compatible server policies. Do not add credentials automatically.
4. Specify local process commands from actual package scripts, host binding and proxy target. For production, record Workers ownership of assets, framework server requests and deep routes, API routing, cache policy, Vite base path, allowed browser origin and authentication callback URLs. Asset manifest integration applies if the backend renders HTML; it is not automatically necessary for a separately hosted SPA.
5. Characterize login/logout/expiry, forbidden records, API outage, reload on a deep URL and environment-specific origin before implementation. Run existing build/type/test checks; use browser proof for actual auth and routing. Report missing backend ownership or provider configuration as unresolved.

Worked [separate-backend decision](../examples/outcome-modernization.md#separate-backend). Applying this procedure does not establish a working application or deployment without its stated native evidence.
